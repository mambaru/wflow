# 06. Реконфигурация

В учебной программе настройки часто зашиты в коде: пять потоков, лимит очереди такой‑то, и всё. В долгоживущем сервисе так жить неудобно. Ночью нагрузка одна, днём другая; иногда нужно срочно сузить пул или поднять потолок очереди. Перезапускать процесс ради этого — дорого: рвутся соединения, теряется прогрев кэшей, растёт простой.

Поэтому в wflow можно **применить новые опции к уже работающему** `workflow`, не уничтожая объект и не обязательно останавливая весь процесс.

## Как это выглядит

Полный сценарий — [`example08.cpp`](../../examples/example08.cpp). Кратко по сюжету:

1. Workflow стартует с тремя потоками.
2. С отдельного потока в него непрерывно сыплются пустые задания — имитация нагрузки.
3. Таймер раз в 100 мс увеличивает счётчик времени.
4. На отметке «20» конфигурацию меняют на `threads = 0` (работаем без своего пула).
5. На отметке «40» поднимают `threads = 6`.
6. На «60» останавливают цикл.

Фрагмент из таймера:

```cpp
opt.threads = 3;
wflow::workflow wf(ios, opt);
wf.start();

wf.create_timer(
  std::chrono::milliseconds(100),
  [&time_counter, &wf, &opt, &ios](){
    time_counter = time_counter + 1;
    if ( time_counter == 20 )
    {
      opt.threads = 0;
      wf.reconfigure(opt);
    }
    else if ( time_counter == 40 )
    {
      opt.threads = 6;
      wf.reconfigure(opt);
    }
    else if ( time_counter == 60)
      ios.stop();
    return time_counter < 60;
  });
```

Запустите пример и смотрите на идентификаторы потоков в выводе: после реконфигурации картина меняется, хотя программа не перезапускалась. Это и есть главная демонстрация главы.

## Что реконфигурация делает и чего не делает

**Делает:** меняет дальнейшее поведение — число рабочих потоков, лимиты и другие поля опций, которые вы передали.

**Не делает:** не отменяет уже принятые задания и не «обнуляет» очередь одним щелчком. Если в очереди лежала тысяча задач, они никуда не денутся только потому, что вы уменьшили `threads`. Просто разбирать их станет меньшее число исполнителей (или цикл `io_context`, если пул убрали).

Когда потоков становится меньше, лишние рабочие потоки корректно завершаются. Не ждите мгновенного чуда: часть работы ещё докрутится.

## Как этим пользоваться «по-взрослому»

В учебном примере ручки крутят по таймеру — так нагляднее. В настоящем сервисе параметры меняют по **наблюдениям**: растёт задержка, растёт число drop, очередь долго сидит у `wrnsize`, CPU простойный или наоборот забит. Без метрик реконфигурация превращается в угадайку.

Для курсовой достаточно показать, что вы понимаете механизм и эффект. Для продакшена рядом должны быть графики и понятные пороги, когда конфигурацию вообще трогают.
